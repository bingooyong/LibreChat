# 输出格式约定

各表格的字段定义。所有引用必须能回溯到原文位置。

## 1. 招标文件摘要

自由文本 + 关键字段表：

| 字段 | 值 | 来源 |
| -- | -- | -- |
| 项目名称 | | 文件名/首页 |
| 招标编号 | | |
| 招标人 | | |
| 采购预算 | | 金额 + 原文表述 |
| 投标截止时间 | | 含时区 |
| 开标时间 | | 含时区 |
| 文件版本 | | 正文/补遗/答疑 |

摘要后的「文件清单」列出每个文件：名称、类型、页数、版本关系。

## 2. 资格条件检查表

| 编号 | 类别 | 条款原文 | 位置 | 企业情况 | 判定 | 说明 |
| -- | -- | -- | -- | -- | -- | -- |
| Q-01 | 资质/业绩/人员/财务/联合体/其他 | | 第X页 第X节 | | 满足/不满足/缺证据/待确认 | |

- 「位置」格式：`第 <页码> 页 · <章节名>`（Word 则为 `第 <章节号> 节`）
- 「企业情况」只填用户材料中确实存在的内容；无材料则填 `未提供`

## 3. 否决项清单

| 编号 | 条款原文 | 位置 | 不满足的后果 | 企业风险 | 需人工确认 |
| -- | -- | -- | -- | -- | -- |
| R-01 | | | 投标无效/废标/不予受理 | 高/中/低 | 是/否 |

「需人工确认」列说明该项是否需要法务或投标负责人判断。

## 4. 评分规则矩阵

| 编号 | 评分项 | 分值 | 评分细则 | 计算方式 | 主观/客观 |
| -- | -- | -- | -- | -- | -- |
| S-01 | 商务/技术/价格 | | | | |

**总分校验**单独列出：

```
分项合计: <X> 分
文件声明总分: <Y> 分
结论: 一致 / 不一致（差 <Z> 分）
差异明细: <逐条列出>
```

## 5. 技术响应矩阵

| 编号 | 招标要求 | 企业响应 | 证据来源 | 符合状态 | 风险 |
| -- | -- | -- | -- | -- | -- |
| T-01 | | | | 完全符合/部分符合/不符合/缺少证据/待人工确认 | |

约束：

- 「证据来源」格式：`<材料文件名> 第 <页码> 页`；无则填 `无`
- 「缺少证据」≠「完全符合」。缺证据时符合状态必须为「缺少证据」
- 「企业响应」为空且无证据时，符合状态为「缺少证据」

## 6. 企业资质与业绩缺口

| 编号 | 缺口项 | 招标要求 | 企业现状 | 差距 | 补救可能性 | 建议动作 |
| -- | -- | -- | -- | -- | -- | -- |
| G-01 | 资质/业绩/人员/财务 | | | 完全/部分满足 | 高/中/低 | |

「补救可能性」按时间是否来得及判断，不做无依据的乐观假设。

## 7. 投标风险

按严重度排序。每条包含：风险描述、触发条件、影响、建议动作、是否需要人工决策。

区分两类风险：

- **合规风险**：不满足即废标
- **得分风险**：不满足会失分但不废标

## 8. 后续工作建议

分三组：

1. **必须完成（否则废标）**
2. **影响得分（按性价比排序）**
3. **需要确认的事项**

每条给出具体动作和责任提示，不代替用户做决策。

## 全局格式约定

- 使用 Markdown 表格；列多时按编号分组输出，避免一张超宽表
- 每个表格前用二级标题标注编号与名称
- 所有结论性语句后附引用位置
- 不使用 emoji
- 报告开头给出「文件清单」和「本次分析覆盖范围」，说明哪些文件已读、哪些未能解析
